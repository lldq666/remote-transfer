# remote_transfer.sh —— SSH 远端文件夹传输脚本

一个交互式的 Bash 脚本：把本机某个文件夹通过 SSH 传到远端 Linux 服务器，
全程中文提示，带输入校验、密码验证、失败重试和实时传输进度。

## 依赖

| 组件 | 是否必需 | 说明 |
| --- | --- | --- |
| `ssh` | 必需 | openssh-client。缺失时脚本尝试自动安装 |
| `sshpass` | 可选 | 自动输入密码。缺失时脚本尝试自动安装，装不上则自动降级为**零第三方依赖**方案 |
| `rsync` | 可选 | 在**本机与远端都存在**时使用，能显示总进度、速度和预计剩余时间 |
| `pv` | 可选 | 没有 rsync 时的降级方案（tar + pv），同样显示速度与剩余时间 |

脚本启动时自检依赖，不再"缺东西就退出"。

## 依赖自检、自动安装与零依赖降级

启动后 `ensure_deps` 依次检查，全部自动，无需用户记命令：

1. **ssh 客户端**：缺失时按包管理器自动安装（`apt-get` → `openssh-client`，
   `dnf/yum/zypper` → `openssh-clients`，`pacman/apk` → `openssh`）；装不上则打印手动命令并退出。
2. **密码注入后端**：见下节。
3. **rsync / pv**：只检测、不安装——它们只影响"速度与剩余时间"的显示效果，
   不影响能否传输，因此不值得为它改动系统。

### 两种密码注入方案

| 方案 | 触发条件 | 原理 | 适用场景 | 限制 |
| --- | --- | --- | --- | --- |
| `sshpass` | 机器上有，或自动安装成功 | 通过伪终端把密码喂给 ssh | 通用，所有 OpenSSH 版本；`rsync -e ssh` 场景最稳 | 需要安装第三方包；部分发行版仓库未收录 |
| `askpass-native` | 无 sshpass，且 OpenSSH ≥ 8.4 | 设 `SSH_ASKPASS` + `SSH_ASKPASS_REQUIRE=force`，让 ssh 直接向辅助脚本取密码 | 无法安装软件的精简系统、容器、只读根文件系统、CI | 依赖 OpenSSH 8.4+（2020 年后基本都满足）；密码经环境变量传给子进程 |
| `askpass-setsid` | 无 sshpass，且 OpenSSH < 8.4 但有 `setsid` | 用 `setsid -w` 脱离控制终端，让 ssh 走 askpass 分支 | 老系统（CentOS 7 等） | 需要 util-linux 的 `setsid`；busybox 版 `setsid` 不支持 `--wait`，可能拿不到准确的退出码 |

自动安装只在**有 root 或 sudo** 时尝试；没有提权能力就直接走零依赖方案，不会卡住流程。
选 `sshpass` 是因为它最稳；选 askpass 是因为它零依赖——两者对上层传输逻辑完全等价，
调用处只经过 `pw_run` 一个入口，`ssh` / `scp` / `rsync` 的原始参数一个没改。

askpass 辅助脚本里**不写密码**，只回显环境变量 `RTRANSFER_SSH_PASS`；
脚本放在 `mktemp -d` 生成的 700 目录里，退出时（含 Ctrl+C）自动删除。

## 使用

```bash
chmod +x remote_transfer.sh
bash remote_transfer.sh
```

按提示依次输入：

1. 远端地址（IP / 域名）
2. SSH 用户名
3. SSH 端口（`1-65535`，默认端口要显式填 `22`）
4. 密码（不回显）
5. 本机要传的文件夹路径
6. 远端接收目录
7. **是否覆盖远端已存在的同名文件（y / n，只问一次，作用于本次全部传输）**

传输结束后会打印最终路径和远端占用空间。

## 流程与校验规则

**第 1 步 · 连接信息**
地址、用户名、端口、密码逐项校验非空；端口必须是 1–65535 的数字，否则重新输入。
拿到信息后会真正执行一次 `ssh 'printf __SSH_OK__'` 来验证密码，而不是只看返回码。

**连接失败**
把 stderr 归类成人话再提示，例如「密码错误，或该账号不允许密码登录」
「端口未开放（SSH 服务未启动，或端口填错了）」「网络不可达或被防火墙拦截」
「服务器地址无法解析」。然后询问 `[Y=重试 / q=退出]`，回车默认重试，重试会重新采集全部连接信息。

**第 2 步 · 本机源目录**
循环校验直到有效，分别提示：路径为空 / 路径不存在 / 不是目录（是普通文件）/
没有读权限 / 无法进入该目录。通过后用 `cd && pwd -P` 转成绝对路径，避免相对路径在
后续 `rsync` 中出问题；空目录只警告，不阻断。

**第 3 步 · 远端目标目录**
用一条远端脚本判断状态并回传标记：

- 已存在且可写 → 直接使用
- 已存在但是普通文件 → 报错并要求换路径
- 已存在但不可写 → 报错并要求换路径
- 不存在 → `mkdir -p` 创建（自动补全多级父目录）；创建失败会打印远端 mkdir 的原始报错，
  并提示常见原因（上级目录无权限 / 磁盘满 / 只读文件系统）

**第 3.5 步 · 覆盖策略**
在传输开始前统一询问一次 `[y=覆盖 / n=不覆盖]`，该选择作用于本次所有传输，之后不再重复询问。
校验是严格的：只接受单个字母 `y` / `Y` / `n` / `N`；空输入、`yes`、`y `（带空格）、
`x` 等一律提示错误并重新询问，直到输入合法。

**第 4 步 · 传输**
按可用性自动选择方案，每种方案都按上一步的选择落实覆盖行为：

1. 本机与远端都有 rsync → `rsync -a --partial --human-readable --info=progress2 --stats -s`
   （rsync < 3.1 自动退回 `--progress`）；选 `n` 时追加 `--ignore-existing`
2. 没有 rsync 但本机有 pv → `tar -cf - | pv -pterb | ssh 'tar -xf -'`；选 `n` 时远端
   解包加 `--skip-old-files`（非 GNU tar 退 `-k`）
3. 两者都没有 → 选 `y` 用 `scp -r`；选 `n` 时因为 scp 无法跳过单个文件，自动改用
   `tar` 管道（无需任何第三方程序），确保"不覆盖"真正生效

传输结果按 `rsync`/`scp`/`tar` 退出码判断，失败时打印原因并以非 0 退出。

## 覆盖策略对照

| 选择 | rsync | tar 管道 | scp（仅选 y 时使用） |
| --- | --- | --- | --- |
| `y` 覆盖 | 默认行为 | 默认行为（覆盖） | 覆盖 |
| `n` 不覆盖 | `--ignore-existing`：跳过接收端已存在的文件 | `--skip-old-files`（GNU tar）/ `-k`（其他） | 不适用，自动切换为 tar 管道 |

语义说明：`n` 是"跳过已存在的文件"，而不是"整个目录已存在就全跳过"——
远端缺失的文件仍会补齐，已有文件保持原样。

## 路径安全（空格与特殊字符）

- 本地路径全部用 `"$var"` 加 `--` 传递，`read -r` 保留空格
- 手工展开 `~`，并自动去掉用户粘贴时带的一对引号
- 远端路径不拼进 shell 命令字符串，而是先 `base64` 编码，到远端再 `base64 -d` 还原，
  因此空格、`$`、`'`、`*`、中文全部安全，不会被远端 shell 二次解释
- `rsync` 加 `-s`（`--protect-args`），远端路径不经过远端 shell 展开
- 主机为 IPv6 时自动加 `[]`，兼容 `user@[addr]:path` 写法

## 安全与退出

- `trap cleanup EXIT`：无论成功、失败、Ctrl+C 还是 `TERM`，都会删除临时文件
  （含 askpass 辅助脚本及其目录）并清空密码变量
- 密码不写进任何文件、不出现在 `ps` 的命令行里：sshpass 走 `SSHPASS` 环境变量（`sshpass -e`），
  askpass 走 `RTRANSFER_SSH_PASS` 环境变量，辅助脚本只做 `printf`
- 支持 `StrictHostKeyChecking=accept-new`：首次连接自动接受指纹，指纹变更时仍会拒绝
- 密码只尝试一次（`NumberOfPasswordPrompts=1`），避免账号被反复试错锁定
- 只做「上传」，不删除任何远端已有文件；`rsync` 不带 `--delete`，`n` 模式下也只是跳过而非删除

## 已知限制

- 需要密码登录的账号。仅允许公钥登录的服务器会因 `PubkeyAuthentication=no` 认证失败，
  此时请改用本地密钥 + `ssh-agent`（去掉脚本里 `pw_run` 的密码注入即可）
- 开启了二次验证（TOTP）的服务器无法用固定密码通过
- 远端需要 `base64`（GNU coreutils 或 busybox 均自带）；缺失时会明确报错，不会静默降级
- 自动安装依赖需要 root 或 sudo + 可用的软件源；都没有时会直接走零依赖方案，不会卡住
- 零依赖方案要求 OpenSSH ≥ 8.4，或系统有支持 `--wait` 的 `setsid`；两者都不满足时会提示手动安装 sshpass
- `n` 模式的精确度依赖后端：rsync 与 GNU tar 可精确到单文件；远端非 GNU tar 时用 `-k`，
  已有文件不会被覆盖，但部分实现会把"文件已存在"当作非 0 退出码，此时会明确提示
- 路径中含换行符属于病态情况，不在支持范围内
